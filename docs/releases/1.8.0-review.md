# 1.8.0-preview.1 — Chat and ticket usage

This is a minor feature increment from 1.7: it adds a new user-visible usage
view. It does not publish a release or authorize installation over an active
comparison session.

## Review scope

- Top ten chats/tickets by tokens or dated API-price equivalent.
- Searchable complete list with paging, source/provider/model and time filters.
- Native Codex/Claude Code session titles and explicit session identities for
  additional supported log sources; honest unknown-title/attribution coverage.
- Exact Multica task/session association, ticket grouping and provider-run
  details without adding runtime usage a second time.
- Per-model input, output and cache details, unknown-price coverage and
  provider-specific cache/reasoning treatment.
- Local/paired-device scope and mixed-version consumption compatibility.
- All supported UI languages and desktop/mobile/RTL presentation.

## Verification

- Complete `npm run check` passed on Manjaro, including the existing reset,
  account, device-sync, mobile and history suites plus the new feature tests.
- Aggregation tests cover ticket/session grouping, copied-request deduplication,
  mixed providers, detail sums, coverage, rolling periods and DST boundaries.
- The API fixture covers authentication, validation, native titles, report
  privacy, no-store, unchanged dashboard totals and worker-restart recovery.
- Metadata tests cover exact task/session joins, progressive lookup batches,
  absent integrations and exclusion of runtime amounts and raw agent output.
- Mixed-version tests verify independent legacy origin signatures, upgraded
  metadata transfer, forwarding, encrypted storage, tampering and revocation.
- A Docker image was rebuilt and an isolated Compose instance passed startup,
  HTML, native-title, report/detail API and unchanged total checks with synthetic
  data. The instance and its temporary files were removed afterwards.
- Full-page browser QA passed at desktop and mobile sizes plus Arabic RTL:
  Top 10, 50/15 paging, search, kind/provider/model filters, cost sorting,
  period/timezone, lazy details, keyboard/focus and auth clearing. No page
  errors, external requests or horizontal overflow were observed.
- Independent backend review has no unresolved substantive findings.

- Fresh M1 `npm run dist:mac -- --publish never` passed for source commit
  `2ce3e28`. The universal executable contains both `x86_64` and `arm64`.
- The generated DMG passed `hdiutil verify`; a read-only mount confirmed version
  `1.8.0-preview.1` and byte-identical packaged server, ranking/metadata/sync
  modules, frontend module/styles and German translation against that commit.
- Review artifact: `LLM-Usage-Dashboard-1.8.0-preview.1-mac-universal.dmg`,
  223,304,175 bytes, SHA-256
  `4c36fb1ef75ef54b3579a8de62beb1fc72c2190540fccbb46203b579b3e18817`.
- The build is an unsigned local preview. No GitHub release or updater
  publication was created. The installed desktop app was deliberately kept
  running for the separate ongoing comparison; installing this build and
  verifying the installed desktop runtime remain the next review step.

## Boundaries

Only retained usage records are reconstructable. Web-only conversations without
token records and deleted local logs remain gaps. Prices are catalog-date
equivalents, not actual subscription spending or provider invoices. Optional
Multica enrichment may initially be partial while bounded lookup batches finish.
The existing installed app and the separate Reinhard comparison are preserved.

## Phone-browser follow-up — 1.8.0-preview.2

The paired-phone gateway is a separate runtime consumer. Its GET allowlist now
includes `/api/chat-usage`, so both ranking and expanded details reach the same
report API. Pairing, GET-only access, response sanitization and removal of forced
refresh requests remain in effect. This is a fix within the 1.8 feature, hence
the next preview identifier rather than another minor version increment.

The regression reproduced HTTP 403 for a paired phone before the change. It
now verifies summary/detail data, preserved period/timezone parameters,
unpaired HTTP 401, POST HTTP 405 and exclusion of private source fields.
The complete project check, independent delta review, Docker rebuild and
isolated Compose phone-gateway smoke passed. Full-page browser verification
also passed through the actual gateway after native pairing at mobile size;
this is separate from viewport-only QA. All test services and credentials were
removed afterwards. The physical handset and installed app remain unchanged.

This preview supersedes the first review DMG for phone-browser use. Fresh M1
universal packaging passed for source commit `ac2d319`. The DMG passed
`hdiutil verify`; read-only mounted inspection confirmed version
`1.8.0-preview.2` and byte-identical packaged server, phone gateway, report module
and frontend against that commit. Artifact size: 223,304,079 bytes. SHA-256:
`4f9db0c2d7fa2df22f901c5eb930adf22f2833bfe4cab5293950b13bef3ddf9a`. Installation and verification on the existing
physical handset remain pending so the live comparison app stays unchanged.

## Default phone scope follow-up — 1.8.0-preview.3

The shared frontend initially selects All installations. With device sync
disabled, the chat report now resolves that selection to local usage, matching
the existing dashboard. Explicit unknown device identifiers remain rejected.
This is a correction within the 1.8 feature and uses the next preview identifier.

The API regression reproduced HTTP 400 before the correction. Its composed
check now pairs a native phone gateway with the real backend and verifies the
default All report, timezone, expanded details and unchanged dashboard totals.
Only synthetic logs and isolated credentials are used. The unchanged frontend
retains the previously verified phone-gateway browser and responsive evidence.

The complete project check and independent delta review passed. The rebuilt
Docker image passed the composed backend/paired-phone test under isolated
Compose, including default All selection and expanded details. The container
and network were removed. No live installation or release was changed.
