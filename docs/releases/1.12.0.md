# 1.12.0-preview.4 — Preserve compressed Codex history

Bug fix within the ongoing 1.12 preview: include `.jsonl.zst` rollout archives in lifetime usage without extracting transcripts to disk. Compression and archival preserve session IDs, models, chat attribution and synchronization identities. If a plain and compressed copy coexist, count the session once; unchanged compressed files reuse the private extraction cache after restart.

A damaged compressed source reports a read error instead of silently producing zero usage. Packaged Electron and the current Node 22 Docker/CI runtimes provide native Zstandard streaming; direct Node installations need Node 22.15 or newer to read compressed logs.

Verified: failing-before/passing-after compressed-history regression; source preservation, duplicate copies, all usage windows, sync identity, cache restart and source-error checks; complete `npm run check`; Docker rebuild. CI artifacts are a review build. Publishing remains a separate release action.

# 1.12.0-preview.1 — Manual reset offers

New feature (MINOR): provider cards show saved manual reset offers separately from the regular usage-window reset times.

- Show the remaining number, reset scope, expiry date, 24-hour local time with time zone, and remaining duration.
- Claude reads the optional reset-offer response and can use the matching organization's local Claude Desktop usage cache. Saved observation times remain visible; expired offers are labelled expired.
- Quota cards whose sources do not report manual reset offers say that the information is unavailable. Missing data never means zero resets. The shared display accepts reported offers from any provider.
- The Claude link opens Settings → Usage. Redeeming a reset remains an explicit action in Claude.
- Reset fields are allowlisted: no grant IDs, account identifiers, cookies, tokens, or raw responses are exposed by this feature.

## Mac download and sharing

The existing GitHub Actions workflow builds a universal DMG and ZIP on a macOS runner. A paid Apple Developer account is not required to produce downloadable preview files. These previews have no Developer ID signature or Apple notarization; their first launch may require the recipient's explicit approval in System Settings → Privacy & Security. The application already reports that automatic macOS updates require signing.

Use the exact version's universal DMG for Intel or Apple Silicon recipients. A download is not evidence that it has been installed on another Mac. Do not describe an unsigned preview as notarized or as automatically installed.
